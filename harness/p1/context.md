# P1 context — 기준: docs/prd.md (2026-10-20), docs/domain.md (2026-10-20)

> [가정] 표시는 원문을 그대로 따른다. 원문에 없는 내용은 `미정`으로 적는다.
> 고객 유형 코드: `change`(요금제 변경) · `port`(번호이동) · `new`(완전 신규) · `add`(회선 추가)
> 목적 코드: `more-data`(데이터 늘리기) · `lower-fee`(요금 낮추기) — `change`만 사용
> 약정 값: 12 / 24 / 0(약정 안 함)

## 1. 유저 스토리

US2(조건 직접 입력)는 이번 범위에서 제외되어 넣지 않는다. 스토리 5개.

|---|---|---|---|

## 2. 규칙

| R2 | 첫 달 청구 금액 = 둘째 달부터 청구 금액 + 위약금 | - |
| R3 | 약정 할인 = 원래 월 요금 × 25%. 결합 할인과 각각 원래 월 요금 기준으로 계산해서 뺀다 (한쪽을 먼저 적용한 금액에 다른 쪽을 적용하지 않음) | - |

| R7 | 금액은 원 단위로 보여 준다. 소수점이 생기면 원 단위 미만은 버린다 | [가정] |

| R9 | 추천 대상은 데이터량이 샘플 사용량 이상인 요금제다 | [가정] |

| R12 | 신규 가입 고객(`port`·`new`·`add`): R9 대상 요금제를 둘째 달부터 청구 금액이 낮은 순으로 보여 준다 | [가정] |

### 데이터 (PRD 8장, DOMAIN 5장)

- 샘플 데이터: Plan, PlanBenefit, SampleUsage, CurrentLine / 저장 데이터: Application
- 요금제명·금액은 자리표시자이며 실제 상품이나 금액을 쓰지 않는다 (C2).
- PRD 8장 원문: 이 프로토타입은 내부 검증용이며 배포하지 않는다. 그래서 테스트할 때 실제 이름·이메일을 입력하고 저장해도 된다. 저장은 브라우저 안에서만 하고 서버로 보내지 않는다 (C1).
- DOMAIN 5장: 저장 위치는 프로토타입 안(브라우저 저장소 등)이다 [가정]. 서버에 보내지 않는다.
- Plan: id, name(자리표시자), monthlyFee(할인 전), dataAmount(GB 또는 무제한), throttleSpeed, voice, sms, benefits(→ PlanBenefit), tethering
- PlanBenefit: id, name(자리표시자)
- SampleUsage: customerType(유형별로 하나 [가정]), monthlyDataUsage
- CurrentLine: currentPlanId(`change`), earlyTerminationFee(`change`), bundleDiscount(`change`, `add`)
- Application: id, customerType, purpose(`change`만, 나머지는 비움), contractMonths(12 / 24 / 0), planId, firstMonthAmount(저장 시점 값), monthlyAmount(저장 시점 값), name, email, privacyConsent([가정]), createdAt

## 3. 고객 유형별 차이

| 항목 | change(요금제 변경) | port(번호이동) | new(완전 신규) | add(회선 추가) |
|---|---|---|---|---|
| 샘플 사용량 | 표시 | 표시 | 표시 | 표시 |
| 목적 선택 (`more-data` / `lower-fee`) | 표시 [가정] | 없음 | 없음 | 없음 |
| 지금 요금제와 비교 (화면 2 지금 요금제명·금액, 화면 3 금액 차이) | 표시 [가정] | 없음 | 없음 | 없음 |
| 약정 할인 | 적용 | 적용 | 적용 | 적용 |
| 결합 할인 | 적용 | 없음 | 없음 | 적용 |
| 위약금 | 첫 달에 더함 | 없음 | 없음 | 없음 |
| 첫 달 청구 금액 줄 (화면 4) | 표시 | 없음 | 없음 | 없음 |
| 추천 규칙 | R10(`more-data`) / R11(`lower-fee`) | R12 | R12 | R12 |
| CurrentLine 사용 | currentPlanId, earlyTerminationFee, bundleDiscount | 없음 | 없음 | bundleDiscount |
| Application.purpose | `more-data` / `lower-fee` | 비움 | 비움 | 비움 |

## 5. 어기면 안 되는 것

- A 정렬 (R8, R14)
  - 정렬·비교 기준은 둘째 달부터 청구 금액(`monthlyAmount`) 하나뿐이다. 낮은 순.
  - 인센티브 등 고객에게 보이지 않는 기준으로 순서를 바꾸지 않는다 [가정].
  - 화면 3에 추천 근거("샘플 사용량 ○GB 기준", R13 [가정])와 정렬 기준 문구([가정])를 보여 준다.
- B 개인정보 (R15)
  - 받는 정보는 이름과 이메일뿐이다. 그 외 개인정보(연락처, 결제 수단 등)는 받지 않는다 (DOMAIN 6장).
  - 이름·이메일은 화면 5에서만 받는다 (R16). 저장 전 동의를 받는다 (R17 [가정]).
  - 저장은 브라우저 안에서만 하고 서버로 보내지 않는다 (PRD 8장, C1, N2).

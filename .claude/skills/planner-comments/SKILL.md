# planner-comments: 기획자용 한국어 주석 달기

화면 코드(React, Vue, HTML, Android XML, Swift 등 언어 무관)에 기획자가 코드를 몰라도 화면 흐름을 이해할 수 있는 한국어 주석을 추가한다. 언어는 코드를 보고 자동으로 판단한다.

## 작업 순서

1. **범위 확인**: 사용자가 지정한 파일이나 폴더만 대상으로 한다. 지정하지 않았으면 작업하지 말고 먼저 묻는다.
2. **원본 기록**: 수정 전 파일 내용을 기억해 둔다. 끝난 뒤 비교할 때 쓴다.
3. **화면 요약 후 확인**: 파일을 읽고 "이 화면은 ○○ 화면으로 보입니다" 식으로 짧게 요약한다. 사용자 확인을 받은 뒤 주석을 단다.
4. **3단계 주석 달기**
   - ① 파일 맨 위: 이 화면이 무엇이고 언제 보이는지
   - ② 영역별: 헤더, 목록, 버튼 영역처럼 덩어리 단위
   - ③ 동작별: 버튼을 누르면 어떻게 되는지, 조건에 따라 무엇이 보이고 숨는지
5. **기존 주석**: 지우거나 고치지 않는다. 그 옆에 새 주석을 추가한다.
6. **여러 파일**: 한 파일씩 처리하고, 파일마다 바꾼 내용을 짧게 보고한 뒤 다음 파일로 넘어간다.
7. **끝났는지 확인**: 아래 "끝났는지 확인"을 수행한 뒤 완료 보고를 한다.

## 결과 형태

- 원본 코드 파일에 주석을 바로 추가한다. 새 파일은 만들지 않는다.
- 기획자용 요약 문서(`.md`)는 사용자가 요청할 때만 만든다.
- 모든 주석 앞에 `[기획]`을 붙인다.
  - 예: `// [기획] 로그인 버튼: 누르면 아이디와 비밀번호를 확인한 뒤 메인 화면으로 이동`
- 언어별 기본 주석 문법을 따른다. 한 줄에 다 들어가지 않으면 여러 줄로 쓴다.
  - JS/TS: `//` 또는 `/* */`
  - JSX/TSX 마크업 안: `{/* */}`
  - HTML, Vue 템플릿, XML: `<!-- -->`
  - CSS: `/* */`
  - Swift/Kotlin: `//`

## 꼭 지킬 것

1. **코드는 바꾸지 않는다.** 주석만 추가하고, 기존 코드는 들여쓰기와 줄바꿈까지 그대로 둔다.
2. **화면에서 보이는 말로 쓴다.** 개발 용어 대신 쉬운 말을 쓰고, 꼭 필요한 개발 용어는 괄호로 덧붙인다.
   - `state` → "화면에 기억해 두는 값(state)"
   - `API 호출` → "서버에서 정보를 받아옴(API 호출)"
3. **추측해서 단정하지 않는다.** 코드만으로 의도를 알 수 없으면 `[기획] (확인 필요) …`로 쓰고 완료 보고에 따로 모은다.
4. **민감 정보는 옮기지 않는다.** 코드에 고객 정보나 테스트용 실제 데이터(이름, 전화번호 등)가 있어도 주석과 보고에 쓰지 않는다. 비밀번호, 키, 토큰 값도 쓰지 않는다.
5. **짧게 쓴다.** 주석 하나는 1~2문장으로 쓴다. 단순 import나 닫는 괄호처럼 코드만 봐도 뻔한 줄에는 달지 않는다.

## 끝났는지 확인

1. **코드 불변**: 원본과 비교해서 달라진 부분이 주석 줄뿐인지 확인한다.
2. **누락 점검**: 다음 세 곳에 주석이 있는지 확인한다.
   - 파일 맨 위 화면 설명
   - 주요 영역
   - 사용자가 조작하는 요소(버튼, 입력창 등)와 조건에 따라 보이거나 숨는 부분
3. **가독성 점검**: `[기획]` 주석만 모아 읽었을 때 코드를 보지 않아도 화면 흐름이 이해되는지 확인한다. 설명 없이 남은 개발 용어가 있으면 고친다.
4. **문법 점검**: 프로젝트에 린트나 빌드 명령이 있으면 실행한다. 없으면 주석 문법이 맞는지 직접 확인한다.

## 완료 보고 형식

```
## 주석 작업 결과

### <파일명>
- 추가한 주석: N개
- 요약:
  1. …
  2. …
  3. …

### (확인 필요) 목록
- <파일명>:<줄> — 확인이 필요한 내용

### 점검 결과
- 코드 불변: 통과/실패
- 누락 점검: 통과/실패
- 가독성 점검: 통과/실패
- 문법 점검: 통과/실패 (실행한 명령 또는 "직접 확인")
```

# PRD — 요금제 추천·구독 서비스 (프로토타입)

> 작성일: 2026-10-20
> 기준 문서: [DOMAIN.md](DOMAIN.md) — 용어, 규칙 번호(R·C), 데이터 모델은 DOMAIN.md를 따른다.
> 표시 규칙: **[가정]** 은 DOMAIN.md에서 가정으로 표시된 내용이다. 최종 확인 전까지 바뀔 수 있다.

## 1. 개요

### 1.1 한 줄 요약
고객이 상담원 없이 **실제 청구 금액** 기준으로 자기 사용량에 맞는 요금제를 비교하고 신청할 수 있는 모바일 웹 프로토타입.

### 1.2 문제
- 데이터가 부족하거나 요금이 부담되는 고객은 고객센터에 전화한다.
- 상담원은 고객에게 맞는 요금제보다 인센티브가 큰 요금제를 위주로 권한다.
- 고객은 자기 사용량을 정확히 모르고, 약정·위약금·결합 할인 때문에 실제로 얼마를 내게 될지 알기 어렵다.
- 그래서 고객은 "영업 당하는 건 아닐까" 의심하며 거절하고, 매장이나 다른 경로를 다시 찾아간다.

### 1.3 해결 방향
1. 사용량을 먼저 보여 주고, 그 사용량을 근거로 추천한다.
2. 모든 금액을 할인과 위약금까지 반영한 **실제 청구 금액**으로 보여 준다.
3. 추천 순서는 고객에게 보이는 기준(금액)으로만 정한다.
4. 상담원 없이 이름·이메일만으로 신청을 마칠 수 있게 한다.

### 1.4 프로토타입의 목적
실제 서비스 개발 전에, 위 해결 방향이 고객의 불신과 망설임을 줄이는지 확인하기 위한 화면 흐름을 만든다. 외부 연동은 하지 않고 모든 데이터는 샘플이다 (C1, C2).

## 4. 범위

### 4.1 포함
- 고객 유형 선택 (4가지)
- 샘플 사용량 표시, 목적·약정 선택
- 실제 청구 금액 기준 추천 결과와 상세 금액 내역
- 이름·이메일 입력과 신청 저장, 완료 화면

### 4.2 제외
DOMAIN.md 6장을 따른다. 요약하면 로그인, 실제 데이터 조회·처리, 고객 조건 입력(US2), 단말기, 이전 통신사 위약금, 유료 부가서비스, 결제 수단, 상담원·관리자 화면은 하지 않는다.

## 5. 유저 스토리와 인수 조건

### US1 — 사용량 확인
고객은 자기에게 맞는 데이터량을 알기 위해 데이터 사용량을 확인한다.
- [ ] 화면 2에서 고객 유형에 맞는 샘플 월 데이터 사용량이 보인다.
- [ ] 사용량은 GB 단위로 보인다 **[가정]**.

### US3 — 추천 근거 확인
고객은 영업 당하지 않았다고 믿기 위해 추천 요금제가 자기 사용량에 맞춰 나왔는지 확인한다.
- [ ] 화면 3 상단에 "샘플 사용량 ○GB 기준" 같은 추천 근거가 보인다 (R13).
- [ ] 추천 결과는 둘째 달부터 청구 금액이 낮은 순서다 (R8, R10~R12).
- [ ] 화면에 정렬 기준이 문구로 보인다 **[가정]**.

### US4 — 변경 영향 확인
고객은 바꿔서 손해 보지 않기 위해 변경 전에 위약금과 결합 할인을 확인한다.
- [ ] 요금제 변경 고객에게는 화면 4에 위약금과 첫 달 청구 금액이 보인다 (R2, R6).
- [ ] 요금제 변경·회선 추가 고객에게는 결합 할인이 금액 내역에 보인다 (R5).
- [ ] 번호이동·완전 신규 고객에게는 위약금과 결합 할인 줄이 보이지 않는다.

### US5 — 신청
고객은 문제를 해결하기 위해 상담원 없이 요금제를 신청한다.
- [ ] 화면 5에서 이름·이메일을 입력하고 동의하면 신청이 저장된다 (R15~R17).
- [ ] 저장 후 화면 6에 고른 요금제, 금액, 이름이 보인다.
- [ ] 저장된 신청은 새로고침해도 남아 있다 **[가정]**.

### US6 — 실제 청구 금액 비교
요금이 부담되는 고객은 실제 청구 금액을 가장 낮추기 위해 할인과 비용을 모두 합친 금액으로 요금제를 비교한다.
- [ ] 화면 3의 모든 요금제 카드에 둘째 달부터 청구 금액이 보인다.
- [ ] 요금제 변경 고객에게는 지금 요금제 대비 금액 차이가 보인다 **[가정]**.
- [ ] 금액은 R1~R4, R7에 따라 계산된다.

## 6. 화면별 요구사항

### 화면 1 — 고객 유형 선택
| 항목 | 내용 |
|---|---|
| 목적 | 고객이 자기 가입 형태를 고른다 |
| 구성 | 안내 문구, 선택지 4개 (요금제 변경 / 번호이동 / 완전 신규 / 회선 추가), 다음 버튼 |
| 동작 | 하나를 골라야 다음 버튼이 활성화된다 **[가정]** |
| 이동 | 다음 → 화면 2 |

### 화면 2 — 사용량 확인 · 목적·약정 선택
| 항목 | 내용 |
|---|---|
| 목적 | 사용량을 확인하고 추천에 필요한 선택을 한다 |
| 구성 | 샘플 월 데이터 사용량, 목적 선택 (요금제 변경만: 데이터 늘리기 / 요금 낮추기) **[가정]**, 약정 선택 (12개월 / 24개월 / 약정 안 함) **[가정]**, 추천 보기 버튼 |
| 요금제 변경 추가 표시 | 지금 요금제명, 지금 둘째 달부터 청구 금액 **[가정]** |
| 동작 | 필요한 선택을 모두 해야 추천 보기 버튼이 활성화된다 **[가정]** |
| 이동 | 추천 보기 → 화면 3 / 뒤로 → 화면 1 |

### 화면 3 — 추천 결과
| 항목 | 내용 |
|---|---|
| 목적 | 사용량 기준 추천 요금제를 금액과 함께 비교한다 |
| 구성 | 추천 근거 문구, 정렬 기준 문구, 요금제 카드 목록 |
| 요금제 카드 | 요금제명, 데이터량, 둘째 달부터 청구 금액, (요금제 변경만) 지금 대비 금액 차이 |
| 빈 상태 | DOMAIN.md 3장 예외 상황을 따른다: 지금보다 저렴한 요금제가 없거나 사용량을 감당하는 요금제가 없으면 안내 문구와 가장 가까운 요금제를 보여 준다 **[가정]** |
| 이동 | 카드 선택 → 화면 4 / 뒤로 → 화면 2 |

### 화면 4 — 요금제 상세 · 청구 금액 내역
| 항목 | 내용 |
|---|---|
| 목적 | 고른 요금제의 정보와 실제 청구 금액이 어떻게 나왔는지 확인한다 |
| 요금제 정보 | 요금제명, 월 요금, 데이터량, 데이터 다 쓴 뒤 속도, 통화, 문자, 포함 혜택, 테더링·공유 데이터 |
| 금액 내역 | 월 요금 / − 약정 할인 / − 결합 할인 (해당 유형만) / = 둘째 달부터 청구 금액 / + 위약금 (요금제 변경만) / = 첫 달 청구 금액 (요금제 변경만) |
| 이동 | 이 요금제로 신청 → 화면 5 / 다른 요금제 보기 → 화면 3 |

### 화면 5 — 신청 확인 (저장)
| 항목 | 내용 |
|---|---|
| 목적 | 고른 내용을 확인하고 신청을 저장한다 |
| 구성 | 요약 (고객 유형, 요금제명, 약정, 첫 달·둘째 달부터 청구 금액), 이름 입력, 이메일 입력, 개인정보 수집·이용 동의 체크박스 **[가정]**, 신청하기 버튼 |
| 검증 | 이름 필수, 이메일 필수·형식 확인, 동의 필수 **[가정]**. 틀리면 해당 칸 아래에 안내 문구 |
| 상태 | 저장 중: 버튼 비활성화 / 저장 실패: 실패 안내, 입력 내용 유지, 다시 시도 가능 **[가정]** |
| 이동 | 저장 성공 → 화면 6 / 뒤로 → 화면 4 |

### 화면 6 — 신청 완료
| 항목 | 내용 |
|---|---|
| 목적 | 신청이 저장됐음을 알린다 |
| 구성 | 완료 문구, 신청 요약 (요금제명, 약정, 첫 달·둘째 달부터 청구 금액, 이름), 처음으로 버튼 |
| 안내 | 프로토타입이라 실제 변경·개통이나 이메일 발송은 되지 않는다는 문구 **[가정]** |
| 이동 | 처음으로 → 화면 1 |

# DOMAIN.md — 요금제 추천·구독 서비스 (프로토타입)

> 작성일: 2026-10-20
> 근거: 도메인 전문가 인터뷰 2회 (고객 이야기 인터뷰, PRD 사전 인터뷰)
> 표시 규칙: **[가정]** 은 Claude가 제안하고 "추천안으로 진행"으로 승인받은 내용입니다. 표시가 없는 내용은 전문가가 직접 답한 내용입니다.

---

## 0. 배경

데이터가 부족하거나 요금이 부담되는 고객이, 고객센터의 영업 위주 추천 없이 **실제 청구 금액** 기준으로 자기에게 맞는 요금제를 고를 수 있게 하는 모바일 웹 **프로토타입**이다.

**고객 문제 (인터뷰 결과)**
- 고객은 데이터가 부족하거나 요금이 부담될 때 고객센터에 전화한다.
- 상담원이 고객에게 맞는 요금제보다 인센티브가 큰 요금제를 위주로 권한다.
- 고객은 약정·위약금, 결합 해제, "영업 당하는 건 아닐까"를 걱정해 망설이고, 이유를 말하지 않고 거절하기도 한다.
- 거절한 고객은 매장이나 다른 경로에서 해결한다. 얼굴을 보고 상담하니 더 믿고, 거절하기도 어렵기 때문이다.
- 고객은 자기 데이터 사용량을 정확히 모른다 ("영상을 많이 봐요" 수준).

## 1. 용어집

| 용어 | 정의 | 비고 |
|---|---|---|
| 고객 유형 | 고객이 첫 화면에서 직접 고르는 가입 형태. 요금제 변경 / 번호이동 / 완전 신규 / 회선 추가 4가지 | 로그인이 없어서 고객이 직접 고름 |
| 요금제 변경 | 이미 가입한 고객이 지금 회선의 요금제를 바꾸는 것 | "기존 고객"과 같은 뜻 |
| 번호이동 | 다른 통신사에서 번호를 가지고 옮겨 오는 가입 | |
| 완전 신규 | 새 번호로 처음 가입하는 것 | |
| 회선 추가 | 이미 고객인 사람이 새 회선을 하나 더 개통하는 것 | |
| 신규 가입 | 번호이동 + 완전 신규 + 회선 추가를 묶어 부르는 말 | |
| 월 요금 | 요금제에 적힌 기본 월 금액. 할인 전 금액 | 고객이 "월 요금"이라고 할 때는 보통 **실제 청구 금액**을 뜻하므로 화면 문구에서 구분해야 함 |
| 포함 혜택 | 요금제에 **포함된** 혜택 (예: OTT 구독) | 인터뷰 초반의 "부가서비스"와 같은 뜻. 따로 돈을 내는 서비스가 아님 |
| 약정 할인 | **선택약정 할인**. 원래 월 요금의 25%. 12개월 또는 24개월 약정 | 단말기 구매가 없으므로 선택약정만 다룸 |
| 결합 할인 | 다른 상품과 결합해서 받는 할인 금액 | 요금제 변경·회선 추가 고객에게만 적용 |
| 위약금 | 요금제 변경 시 기존 약정을 깨면서 내는 돈. 한 번만 냄 | 요금제 변경 고객에게만 적용. 이전 통신사 위약금은 다루지 않음 |
| 실제 청구 금액 | 고객이 실제로 내는 금액. 아래 두 가지로 나뉨 | 고객이 요금제를 비교하는 기준 |
| 둘째 달부터 청구 금액 | 월 요금 − 결합 할인 − 약정 할인 | **정렬과 비교의 기준** |
| 첫 달 청구 금액 | 둘째 달부터 청구 금액 + 위약금 | 요금제 변경 고객에게만 둘째 달 금액과 다름 |
| 샘플 사용량 | 프로토타입에서 실제 사용량 조회를 대신하는 가짜 월 데이터 사용량 | 4가지 유형 모두에 사용 |
| 목적 | "데이터 늘리기" 또는 "요금 낮추기" | **[가정]** 요금제 변경 고객만 고름 |
| 신청(저장) | 이름·이메일과 고른 요금제를 프로토타입 안에 저장하고 완료 화면을 보여 주는 것 | 실제 변경·개통·이메일 발송은 하지 않음 |

## 2. 역할

| 역할 | 목표 |
|---|---|
| 고객 (요금제 변경) — 데이터 부족 | 데이터 부족을 해결하면서, 받아들일 수 있는 금액 안의 요금제를 고른다 |
| 고객 (요금제 변경) — 요금 부담 | 실제 청구 금액이 가장 낮은 요금제를 고른다 |
| 고객 (신규 가입: 번호이동·완전 신규·회선 추가) | 사용량에 맞으면서 실제 청구 금액이 낮은 요금제를 골라 신청한다 |

- 이 프로토타입의 사용자는 **고객 한 역할**뿐이다. 상담원·관리자 화면은 없다.

### 유저 스토리
| # | 유저 스토리 | 이번 범위 |
|---|---|---|
| US1 | 고객은 자기에게 맞는 데이터량을 알기 위해 데이터 사용량을 확인한다. | 포함 (샘플 사용량) |
| US2 | 고객은 마음속 금액 안에서 절충안을 찾기 위해 조건을 스스로 정한다. | **제외** (조건 입력 없음) |
| US3 | 고객은 영업 당하지 않았다고 믿기 위해 추천 요금제가 자기 사용량에 맞춰 나왔는지 확인한다. | 포함 |
| US4 | 고객은 바꿔서 손해 보지 않기 위해 변경 전에 위약금과 결합 할인을 확인한다. | 포함 (샘플 데이터) |
| US5 | 고객은 문제를 해결하기 위해 상담원 없이 요금제를 신청한다. | 포함 (저장만) |
| US6 | 요금이 부담되는 고객은 실제 청구 금액을 가장 낮추기 위해 할인과 비용을 모두 합친 금액으로 요금제를 비교한다. | 포함 |

## 3. 흐름

### 화면 목록 (6개)
| # | 화면 | 하는 일 | 스토리 |
|---|---|---|---|
| 1 | 고객 유형 선택 | 4가지 유형 중 하나를 고른다 | — |
| 2 | 사용량 확인 · 목적·약정 선택 | 샘플 사용량을 보여 준다. 요금제 변경 고객은 목적을 고른다 **[가정]**. 약정(12개월 / 24개월 / 약정 안 함)을 고른다 **[가정]** | US1 |
| 3 | 추천 결과 | 요금제 목록을 둘째 달부터 청구 금액과 추천 근거와 함께 보여 준다 | US3, US6 |
| 4 | 요금제 상세 · 청구 금액 내역 | 요금제 정보 8가지와 금액 내역(월 요금, 약정 할인, 결합 할인, 위약금, 첫 달·둘째 달 금액)을 보여 준다 | US3, US4, US6 |
| 5 | 신청 확인 **(저장)** | 고른 요금제와 금액을 다시 보여 주고 이름·이메일을 받아 저장한다 | US5 |
| 6 | 신청 완료 | 저장된 신청 내용을 보여 준다 | US5 |

### 기본 흐름
```
1 고객 유형 선택
 → 2 사용량 확인 · 목적·약정 선택
 → 3 추천 결과
 → 4 요금제 상세 · 청구 금액 내역 ──(다른 요금제 보기)──> 3
 → 5 신청 확인 (이름·이메일 입력 → 저장)
 → 6 신청 완료
```

### 유형별 차이
| 항목 | 요금제 변경 | 번호이동 | 완전 신규 | 회선 추가 |
|---|---|---|---|---|
| 샘플 사용량 | 표시 | 표시 | 표시 | 표시 |
| 목적 선택 (데이터 늘리기 / 요금 낮추기) | 표시 **[가정]** | 없음 | 없음 | 없음 |
| 지금 요금제와 비교 | 표시 **[가정]** | 없음 | 없음 | 없음 |
| 약정 할인 | 적용 | 적용 | 적용 | 적용 |
| 결합 할인 | 적용 | 없음 | 없음 | 적용 |
| 위약금 | 첫 달에 더함 | 없음 | 없음 | 없음 |

### 예외 상황
| 상황 | 처리 |
|---|---|
| "요금 낮추기"인데 지금 요금제보다 저렴한 요금제가 없음 | "지금보다 저렴한 요금제가 없어요"라고 알리고, 사용량을 감당하는 요금제 중 가장 저렴한 것을 함께 보여 준다 **[가정]** |
| 샘플 사용량을 감당하는 요금제가 없음 | 데이터량이 가장 큰 요금제부터 보여 주고 사용량보다 적다고 알린다 **[가정]** |
| 이름이나 이메일을 비워 둠 / 이메일 형식이 틀림 | 저장하지 않고 해당 칸에 안내 문구를 보여 준다 **[가정]** |
| 개인정보 수집·이용에 동의하지 않음 | 저장하지 않는다 **[가정]** |
| 저장 실패 | 실패를 알리고 다시 시도하게 한다. 입력한 내용은 지우지 않는다 **[가정]** |

## 4. 비즈니스 규칙

### 금액 계산
- R1. **둘째 달부터 청구 금액** = 월 요금 − 결합 할인 − 약정 할인
- R2. **첫 달 청구 금액** = 둘째 달부터 청구 금액 + 위약금
- R3. 약정 할인 = **원래 월 요금 × 25%**. 결합 할인과 각각 원래 월 요금 기준으로 계산해서 뺀다 (한쪽을 먼저 적용한 금액에 다른 쪽을 적용하지 않음)
- R4. 약정 안 함을 고르면 약정 할인은 0이다 **[가정]**
- R5. 결합 할인은 요금제 변경·회선 추가 고객에게만 적용한다
- R6. 위약금은 요금제 변경 고객에게만 적용한다. 번호이동 고객의 이전 통신사 위약금은 넣지 않는다
- R7. 금액은 원 단위로 보여 준다. 소수점이 생기면 원 단위 미만은 버린다 **[가정]**

### 추천과 정렬
- R8. 정렬과 금액 비교의 기준은 **둘째 달부터 청구 금액**이다
- R9. 추천 대상은 데이터량이 샘플 사용량 이상인 요금제다 **[가정]**
- R10. 데이터 늘리기: 지금 요금제보다 데이터량이 많은 요금제를 둘째 달부터 청구 금액이 낮은 순으로 보여 준다 **[가정]**
- R11. 요금 낮추기: 둘째 달부터 청구 금액이 지금 요금제보다 낮은 요금제를 낮은 순으로 보여 준다 **[가정]**
- R12. 신규 가입 고객: R9 대상 요금제를 둘째 달부터 청구 금액이 낮은 순으로 보여 준다 **[가정]**
- R13. 추천 결과에는 "샘플 사용량 ○GB 기준"처럼 **추천 근거**를 함께 보여 준다 **[가정]** — 영업 불신(US3)을 줄이기 위함
- R14. 인센티브 등 고객에게 보이지 않는 기준으로 순서를 바꾸지 않는다 **[가정]**

### 신청
- R15. 신청 시 받는 정보는 **이름과 이메일**뿐이다
- R16. 이름·이메일은 요금제를 고른 뒤 신청 직전(화면 5)에 받는다
- R17. 저장 전 개인정보 수집·이용 동의를 받는다 **[가정]**
- R18. 신규 가입은 **요금제만** 고른다. 단말기 구매는 없다

### 제약
- C1. 프로토타입이다. 외부 시스템 연동(로그인, 사용량 조회, 위약금·결합 계산, 개통, 이메일 발송)은 하지 않는다
- C2. 요금제·사용량·위약금·결합 할인은 모두 **샘플 데이터**다. 실제 상품명이나 금액을 쓰지 않는다
- C3. 모바일 웹이다

## 5. 데이터 모델

```
CustomerType ─┐
              ├─< Application >── Plan ──< PlanBenefit
CurrentLine ──┘                     │
(요금제 변경·회선 추가만)            └── (참조) SampleUsage
```

### Plan (요금제) — 샘플 데이터
| 필드 | 설명 |
|---|---|
| id | 식별자 |
| name | 요금제명 (자리표시자) |
| monthlyFee | 월 요금 (할인 전) |
| dataAmount | 데이터량 (GB 또는 무제한) |
| throttleSpeed | 데이터 다 쓴 뒤 속도 |
| voice | 통화 |
| sms | 문자 |
| benefits | 포함 혜택 목록 → PlanBenefit |
| tethering | 테더링·공유 데이터 |

### PlanBenefit (포함 혜택) — 샘플 데이터
| 필드 | 설명 |
|---|---|
| id | 식별자 |
| name | 혜택 이름 (예: OTT 구독, 자리표시자) |

### SampleUsage (샘플 사용량)
| 필드 | 설명 |
|---|---|
| customerType | 고객 유형별로 하나 **[가정]** |
| monthlyDataUsage | 월 데이터 사용량 |

### CurrentLine (지금 회선) — 요금제 변경·회선 추가 고객용 샘플 데이터
| 필드 | 설명 | 사용 유형 |
|---|---|---|
| currentPlanId | 지금 요금제 → Plan | 요금제 변경 |
| earlyTerminationFee | 위약금 | 요금제 변경 |
| bundleDiscount | 결합 할인 금액 | 요금제 변경, 회선 추가 |

### Application (신청) — 저장 대상
| 필드 | 설명 |
|---|---|
| id | 식별자 |
| customerType | 고객 유형 |
| purpose | 목적 (요금제 변경만, 나머지는 비움) |
| contractMonths | 약정 (12 / 24 / 0) |
| planId | 고른 요금제 → Plan |
| firstMonthAmount | 첫 달 청구 금액 (저장 시점 값) |
| monthlyAmount | 둘째 달부터 청구 금액 (저장 시점 값) |
| name | 이름 |
| email | 이메일 |
| privacyConsent | 개인정보 수집·이용 동의 여부 **[가정]** |
| createdAt | 신청 시각 |

- 저장 위치는 프로토타입 안(브라우저 저장소 등)이다 **[가정]**. 서버에 보내지 않는다.

## 6. 이번 범위에서 하지 않을 것

- 로그인 / 본인인증
- 실제 사용량·위약금·결합 정보 조회 (샘플 데이터로 대체)
- 고객이 직접 조건(금액, 데이터량, 혜택)을 입력하는 기능 (US2)
- 실제 요금제 변경·개통 처리, 이메일 발송
- 단말기 구매·할부
- 번호이동 고객의 이전 통신사 위약금
- 돈을 내고 따로 추가하는 부가서비스
- 결제 수단 입력, 이름·이메일 외의 개인정보 입력
- 상담원·관리자 화면

## 7. 열린 질문

1. 샘플 사용량을 고객 유형별로 하나씩 둘지, 여러 시나리오(데이터 부족, 요금 부담 등)를 둘지
2. 약정 기본값을 무엇으로 할지 (12개월 / 24개월 / 약정 안 함)
3. 추천 결과를 몇 개까지 보여 줄지
4. 매장 상담에서 고객이 믿게 되는 구체적인 행동은 무엇인지 — 추천 근거 문구(R13) 설계에 필요
5. 개인정보 수집·이용 동의 문구와 저장 기간 (프로토타입이라도 실제 사용자 테스트를 한다면 필요)
6. 첫 달 청구 금액을 추천 결과(화면 3)에도 보여 줄지, 상세(화면 4)에서만 보여 줄지
7. **[가정]** 으로 표시한 규칙(R4, R7, R9~R14, R17, 예외 처리)이 맞는지 최종 확인
